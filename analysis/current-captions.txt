2. 另一条路径从文件元信息索引取得清单。
3. 两条路径最终服务于文件发现。
4. 当前未实现 Metadata Table，不展示虚构的性能数字。
### A04 (4步)
1. 两条输入通道指向同一个文件组。
2. 两个写者都基于同一个旧版本产生候选更新。
3. 用高亮表示需要校验的冲突位置。
4. 锁、OCC 与实际重试语义未建模，不能当成并发实测。
### A05 (4步)
1. 先增加一次更新，观察模拟 Log 数。
2. 当前演示满足最低候选条件。
3. 执行后当前有效 Log 数减少。
4. 只展示模拟文件和字节数，不换算真实吞吐。
### A06 (4步)
1. 先更新一条已有记录。
2. 再添加提交，使窗口有可淘汰历史。
3. 调整保留数后重新演示，比较文件占用。
4. 实际文件数和估算字节数来自引擎。
### A07 (4步)
1. 初始小批写入生成多个 Instant。
2. 窗口决定迁移到 Archive 的范围。
3. 只迁移元数据，不移动 Parquet 文件。
4. 查询结果与归档前一致，耗时不代表真实集群。
### A08 (4步)
1. 从模拟状态统计文件数、Log、旧版本和 pending。
2. 看到 Log 堆积，选择安排合并。
3. 实际文件结果由引擎计算。
4. 维护建议不能替代真实集群健康诊断。
