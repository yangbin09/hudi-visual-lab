# Hudi Visual Lab

运行 `npm run dev`。首页 `/` 从八个问题进入对应主题，`/catalog` 提供全部 80 个动画入口、模块筛选、范围筛选和搜索。`/experiment/B02` 与 `/experiment/B03` 使用独立的 COW 文件重写与 MOR 版本归并画布，其余 78 个主题进入各自场景。默认只展示画布、当前步骤的一两句话和播放控件。

## 交互

- 统一开始、暂停、单步、上一步、拖动进度、回放、变速、重置和跳到结果。一个 RAF 时钟驱动全部位置，暂停时运动也暂停。
- 单击文件、Bucket、查询结果、Instant、配置或流程节点，打开模态详情。打开时自动暂停；Escape 关闭后恢复触发按钮的焦点，不自动恢复播放。
- 参数在抽屉内编辑，点击“应用参数并重置”后才重新生成场景。无播放中途的数据替换。Bucket 数变化重新计算教学映射，保留数影响实际模拟 Cleaner/Archive。
- 系统减少动态效果时使用手动逐步观察；设置也可开启。键盘空格播放/暂停，左右箭头单步，输入框和模态操作不被快捷键劫持。
- 预览中的新文件明确标注“尚未提交”；基础原理画布允许检查候选记录并标明其未提交身份，其他画布在提交前禁用新文件。提交阶段文件与 Timeline 同时切换为精确引擎快照。

## 代码

- `src/experiments/visual/lessons.ts`：78 个逐主题步骤定义，包含场景类型、初始条件、操作、教学说明和参数。B02/B03 共享操作回放协议，使用各自独立的教学画布。
- `src/engine/visual/scenarios.ts`：调用 `applyAction`、`performWrite`、`runQuery` 和已有分桶函数；生成不可变的操作前后快照、文件变化与查询结果。Bulk Insert 调用已有公共 `performWrite`，不引入新的 UI 写入规则。
- `src/animation/useLessonPlayer.ts`：统一时钟与状态选择器。seek/back/replay 不重复运行操作。
- `src/components/visual/Animated*.vue`：文件流动、索引分配、查询归并、Timeline、配置结构、组件链路与指标变化七类画布。双 Writer 汇合、Metadata 两条路径、SaveMode 四分支、Checkpoint 屏障有单独结构。
- `src/views/LessonView.vue`：教学壳层和渐进式技术详情。
- `src/views/AnimatedCatalogView.vue`：完整可播放目录。缩略图仅在可见区域播放，并遵循减少动态效果。

## 范围与准确性

目录里的 `implemented` 仍表示旧 ExperimentDefinition 注册情况，不将所有主题虚报为完整引擎实现。新的动画目录单独标记：

- **引擎驱动**：文件、记录、查询结果、分桶、Timeline 和表服务使用现有本地引擎。
- **引擎 + 机制示意**：能执行的部分调用引擎；调度、外部服务或尚未建模的机制明确标为示意。
- **机制示意**：Schema 演进、Spark SaveMode、Checkpoint、权限、Metadata Table、并发等没有完整运行模型，不伪造外部服务执行结果或性能数据。Restore 页面演示历史读取与恢复的区别，不生成虚构 RESTORE 提交。

沿用 HuaweiMRS350R26Profile 和证据库，不连接真实 Spark/Flink/HMS/HDFS。MOR 种子 Base 使用引擎 Bulk Insert 建立；普通更新按照当前规则追加 Log。BUCKET 使用 djb2 教学算法，r26 映射与文件分配待验证。Bloom 候选筛选没有实现真实位图。所有动作只代表当前教学模型，真实语义缺口显示在对应实验和证据抽屉中。

在文件画布中最多显示四个文件；完整物理清单在 HDFS 抽屉。指标中的字节数为引擎估算，不代表现场实测。故障动作直接展示引擎实际返回的 INFLIGHT 等状态，不以作业日志“成功”替换事务结果。

## 核心原理的教学细化

核心步骤增加逐记录教学追踪，保留外层布局和操作方式：

- 写入：保存实际 action 输入，展示旧值、新值、两侧 precombine；不能把设置中的 Upsert 主键当成实际 Insert 新主键。COW 展示未修改记录逐行复制，MOR 展示 Base 保持、仅追加更新 Log。
- 版本比较：同批候选与乱序旧消息展开实际 ts；输出选择依照引擎快照。当前模型忽略旧消息时可能记录 files=[] 的空提交，动画不将空提交画成文件改写。
- 查询：从本次读取范围取出版本，逐项显示跳过原因、同键淘汰原因和实际结果。Read Optimized 的 Log 不流入结果；Time Travel 使用历史 Checkpoint，不能用当前值冒充历史版本；D 在 Snapshot 中过滤，在 Incremental 中保留。
- 合并：把 Base/Log 同键版本并排展示，划去被取代版本，保留其他键并逐行生成新 Base。被取代文件与物理删除仍严格分开。
- 清理：逐文件展开“是否仍被引用”“supersededAt 是否在当前模型的保留集合内”，删除集合与引擎返回完全一致。
- 索引：Bucket 展示 hash 数值、取模式和桶内记录；Hash 节点可查看从 5381 开始的逐 UTF-16 编码单元计算，教学解释与实际哈希调用同一计算路径。SIMPLE/Bloom 使用真实候选文件内容，Bloom 的粗筛/误判仍明确标为示意，不伪装成真实位图执行。
- 事务：对比同一个 Instant 的前后状态，区分新请求、未完成执行、回滚和归档，不再只展示泛化的移动圆点。
- 组件示意：Checkpoint 加入明确标为示例的 offset=101/102/103 与恢复边界；权限链路区分身份认证与资源授权。外部服务仍不宣称真实执行。

`src/engine/visual/teachingTrace.ts` 从真实输入和前后快照推导教学追踪，不修改模拟结果。`RecordWalkthrough.vue`、`CleanerWalkthrough.vue` 和查询画布展示可读的过程；对象详情默认展示记录表和原因，原始 JSON 折叠。

播放器按“定位、比较、生成、提交”等细节停靠，复杂操作放慢自动播放，进度拖动保持精确回放。细节画布采用更紧凑的视区以放大字体，移动记录绕开解释文字；长文件只展示前五行并注明总数。

新增教学验收分别验证实际 Insert 主键、COW 复制行、MOR 追加行、旧消息空提交、版本去留与查询结果一致、Cleaner 保护边界、逐字符哈希、单步阶段准确性，以及四种尺寸下的教学操作。

### E01：用配置对照替代抽象阻断流程

`IndexConfigWalkthrough.vue` 展示固定的表定义 BUCKET 与可修改的作业选项。使用相同主键对照 SIMPLE 的已有键/位置匹配和 BUCKET 的教学哈希取模；位置表中的文件 A/B 明确是示例，不冒充引擎实际文件。用户修改选项后重置并重演，配置比对、路径、解释同步变化，拖动或播放本身不自动修复配置。

最后一章设置四个 authored `LessonStep.moments`，播放器使用与引擎追踪相同的单步、回退和减弱动画控制。E01 删除任意“阻断关口”参数，保留主键和桶数实验。案例假设本次采用所选作业选项，不声称真实优先级、错误类名或配置一致即可恢复写入；真实 r26 根因与重跑结果仍待验证。

## 学习流程与验证改进（2026-10-22）

- 路由按 path 隔离实例：连续点击下一主题不会复用上一课的初始化状态；query 的详情标签切换保留播放，并同步浏览器地址。
- 普通课程保存精确 position、参数与 E01 作业选项，暂停、拖动、离开和 pagehide 都有保存入口；恢复时不自动播放。B02/B03 记录操作序列与位置，通过确定性引擎重建历史，两个主题各自保存。重置实验明确回到初态。
- `quiz.ts` 覆盖 80 个主题：审校的原理判断 + 查询结果/物理文件变化题，机制示意另有证据与控制变量题。结果根据本次参数与最后查询重建，答案位置按主题与题号均衡排列，固定选第一项只能得 33 分。原理题必须正确且总分至少 60 才授予掌握；旧版本自动题成绩失效，保留访问与观看记录。平均分包含本版本零分尝试。
- F04 用 offset 101–104 展示收到、确认边界、故障与恢复：改变确认边界直接改变重放集合。A04 对比同/不同目标的读版本与提交版本，冲突后可重读并重试。两个模型均保持 concept，不修改真实表快照，不宣称 r26 协议已验证；旁白与详情使用同一模型推导。
- 移除 Element Plus 和 ECharts 依赖，证据库保留原有搜索/筛选/文档链接并使用语义 HTML；数据、代码详情异步加载，CodeMirror 不进入首页或课程首屏静态依赖。带控件画布按自然高度布局，避免矮屏重叠。
- `npm run verify` 包含源文件控制字符/CSS 检查、单测、类型检查与构建、manifest 静态依赖体积检查；首页 gzip 上限 100 KiB，课程 220 KiB，单个 JS 文件 350 KiB，并禁止首屏静态加载代码编辑器。体积是压缩产物的静态依赖合计，不代表真实网络耗时。
- GitHub Actions 在 main push / PR 上运行上述检查及四种视口的完整 Playwright 套件；失败保留 trace。`learning-flow.spec.ts` 覆盖路径进入、切课、回退、刷新续播、参数、比较实验、原理题门槛、进度、机制对照及按需加载。

## 基础原理八课的教学画布

- B01：Parquet / Hudi 对照，区分数据文件与事务版本管理，不把普通 Parquet 更新一概描述为整表覆盖。
- B02：旧 Base、输入 ts 比较、逐行复制、新 Base、完成提交。只提供 COW 相关操作，详情区同步 COW 状态。
- B03：Base、多个 Log、Snapshot / Read Optimized 双读取路径与 Compaction 候选。详情区同步 MOR 状态。
- B04：分区 → File Group → File Slice → Base + Logs 的嵌套结构，显示稳定 File ID 与候选文件。
- B05：基于真实 Checkpoint / 当前状态投影文件版本；连续两次更新同一主键，第二次金额增加 100。分别显示 Log version、写入 instant、Slice base instant 与物理保留状态。
- B06：Record Key + Partition Path 组合身份，两个分区的 HoodieKey 与记录存在性并排比较。
- B07：历史时刻与最新已提交时刻两个读者，提交前后的路由与金额对照；可以独立突出读取路径。本地 Checkpoint 只是模拟引擎的历史保存机制。
- B08：可用点击及键盘展开的逻辑目录树，展示实际物理文件与 Timeline 状态；真实目录布局与命名需按版本核对。

`basics-story.ts` 提供六个普通基础课逐步编写的微节拍；B02/B03 使用各自的动作旁白。所有移动、候选透明度与行复制均由播放器位置驱动，暂停和拖动不会继续运行独立 CSS 动画。画布异步加载，手机使用画布内横向滚动。

验证：`tests/unit/basics-principles.spec.ts` 核对版本投影、文件身份、归并结果与历史隔离；`tests/e2e/basics-principles.spec.ts` 核对八种结构、提交可见性、连续更新、键盘目录交互、暂停与画布边界。
